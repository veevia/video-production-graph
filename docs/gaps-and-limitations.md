# Gaps and limitations

> **TL;DR:** vpg proves the *mechanics* of a governed production loop on real media: routing, targeted rework,
> memoisation, resume, packaging, provenance and governed learning. It does not prove craft or perception, and its
> numeric thresholds still need calibrating against Wei's judgement. Items marked **human** can only be closed by a
> named person.

Evidence tags follow the workspace convention:
- `observed` — shown by a test or a dry run in this package;
- `reported` — from the case study or research sources;
- `assumed` — a design judgement not yet tested.

## Limitations of the workflow

| # | Limitation | Evidence | Mitigation / next step |
|---|---|---|---|
| 1 | **Thresholds are requirement-approved but not calibrated.** Values such as 22 px minimum text, −16 LUFS ±1, the 1.8–3.2 words/s pacing band and 8 text layers per scene come from Wei's stated requirements, Round 07 measurements and standards. None is fitted to Wei's accept/reject decisions. Until one is, a limit that fails one scene Wei accepts is set for that scene alone (`thresholds.density.scene_limits` in evaluation.md). Raising the film-wide limit would stop the check for every other scene. | reported (`config/defaults.yaml` names each rule; `pacing` and `density` say "calibration pending") | **human:** record Wei's verdicts on ≥ 2 more productions, then revise the rules through `vpg memory promote` |
| 2 | **Perception cannot be certified.** Adult-professional voice, warmth and music supporting the voice are `human` dimensions. Agents never score them, and release lists them as pending. | observed (`test_voice_direction_requires_adult`; the dry run's approvals are labelled not human) | **human:** a listening pass at N23 |
| 3 | **The text-layer manifest is a proxy for legibility, not for privacy.** Legibility and design audits read the renderer's `text-layers.json`. They cannot see text baked into illustrations or UI captures, or a renderer that draws something other than what its manifest says. Privacy is different: N23 scans the rendered master at native frame rate, and `live_windows` declare moving UI ranges that must be fully decoded. | observed (`tests/test_privacy.py`, `tests/test_publish_and_reuse.py`, `tests/test_privacy_rates.py`) | Keep exporting `text-layers.json` for design checks. Declare live windows for moving UI and keep `privacy.names` tenant-side. A richer area-based OCR audit remains future work. |
| 4 | **Flash detection is a whole-frame proxy.** It counts frame-to-frame mean-luma swings (≥ 0.2, more than 3/s). It is not an area-based WCAG 2.3.1 / ITU-R BT.1702 analyser, so a small bright flash can pass. | observed (`test_flash_detection`) | Run a certified photosensitivity analyser before public release |
| 5 | **Regeneration is per node.** The engine re-runs or skips whole nodes. Re-rendering one scene or one voice unit depends on the project command honouring `defects` in `context.json`. | observed (the dry run re-ran only N14; the sample pipeline re-renders whole nodes) | Document the item-level contract per command, as in the extension guide |
| 6 | **Single machine, one writer at a time.** One process changes a run at a time (`.vpg/lock`). A long `vpg run` render delays agent submissions by up to `--lock-timeout`. There are no distributed workers. The Windows lock fallback is untested. Nodes that write control documents run alone, so N09 no longer runs beside N07. | observed (`tests/test_cli.py`) | Adequate for one production on one workstation. Move to a queue only if productions run concurrently at scale. |
| 7 | **Agents are external.** The engine never calls a model or the network. It writes task packets and waits, so the loop is only as autonomous as the agent or person driving `vpg run` / `vpg submit`. | observed (`test_task_packet_mode_writes_complete_packet`, `test_no_network_imports_in_engine`) | The SOP and `/video-production` prompt define the driving loop for agents |
| 8 | **The dry run proves mechanics, not craft.** The sample uses macOS `say` and PIL scenes. It exercises every control path on real 1080p media, but its voice would fail Wei's adult-professional bar by design. | observed (dry run 18/18) | Real productions bind the approved local TTS pipeline and renderer in `vpg.project.yaml` |
| 9 | **The rule base comes from one production.** 46 rules were distilled from one film's 31 iterations, so generalisation is unproven. No rule has reached `monitored`, because that needs a later production. | reported (case study) | The N25 learning proposals on the next productions |
| 10 | **Truncating the ledger's tail is not detected.** The hash chain catches edited, inserted or deleted events, but not removal of the newest events, because the head hash has no external anchor. | observed (`test_ledger_detects_tampering` covers edits) | Anchor the head hash in checkpoints or commits if audit needs demand it |
| 11 | **Domain tools trace to the default node ids.** A graph that renames N07/N08/N10–N14 must bring its own tools. An unknown trace fails N21's `defects_valid` check, so it is never lost. | observed | See the [extension guide](extension-guide.md) |
| 12 | **Workflow OS is not bridged.** vpg is standalone. | reported ([ADR 0001](adr/0001-graph-engine.md), 🟡, expiry 2026-12-31) | Re-decide by the expiry date |
| 13 | **The case study can be verified only on the recording workstation.** Its 320 cited paths are absolute: 303 in the workspace and 17 in local session state. Some cited renders are not tracked by git. | observed (`test_history_citations_resolve_on_disk` checks every citation and output path when `workspace_root` exists, and otherwise skips with that reason; the reviewer fails A14 on any skip) | Verify on the recording machine. The engine, tools, sample project and all other tests are path-independent. |
| 14 | **Integrity guards trade availability for safety.** Any edit to the package's rules, rubrics, default thresholds, prompts, agent role files or engine code blocks every run in flight until a human accepts it. An unattributable edit to a control document blocks the whole run for review. | observed (`tests/test_hardening.py`) | By design; `vpg accept-config` and `vpg unblock` are the human paths back. |
| 15 | **Stall detection happens at runtime, too.** The validator catches every join a forward outcome can strand. A state reached by hand editing or a rollback can still stall; the engine then blocks with a `no-progress` report instead of hanging. | observed (`test_stranded_join_blocks_instead_of_running_forever`) | Fix the graph or roll back, then unblock. |
| 16 | **Human identity is asserted, not authenticated.** `--actor Wei` is trusted as named. The engine refuses `agent:*` and dry-run actors, in any case and spacing, for every human decision (approve, unblock, gap waiver, rollback, accept-config, rule approval, revision or retirement), and the ledger records who acted. It cannot prove who typed the name. Since v1.7 an agent can act for a human only under the human's dated `vpg grant`, and each such act is ledgered with the grant, so delegated work no longer needs the human's name. | assumed | The SOP and prompt forbid agents from acting as Wei; delegate with `vpg grant` instead. For stronger assurance, run agents under an account without access to those commands, or sign decisions. |
| 17 | **Coverage checks content identity, not truth.** N02 counts a source as product or brand evidence only if all four hold: its file is stored in the project's own `sources/` directory (a symlinked `sources/` counts nothing); it is not a copy of a control document or template; it is not also registered under another kind (the brief included); and it is not assumed. It cannot tell that a distinct file under `sources/` is genuine: an agent that writes its own "spec" there and tags it observed passes the tool check. | observed (critic rounds 5–7: a relabelled brief, the unfilled control templates, then a symlinked `sources/`, cleared both gaps before these checks) | The N04 and N09 human gates list the grounding sources with their evidence tags. Wei checks them there, and product truth and the design system are approved only by a named human. |
| 18 | **Untagged claims are caught by judgment, not by a tool.** The deterministic claims check (ACC-CLAIMS) sees only the claim ids a script declares. A product claim with no id, for example "cuts water costs 40%", is scored by the N19 reviewer under ACC-UNTAGGED (MUST), and the human release review is the backstop. | observed (critic round 14: an untagged 40% claim passed N07 and N19 before ACC-UNTAGGED) | Write every product claim with its verified id. A number-and-outcome scanner could flag candidates for the reviewer, but it would be a heuristic, so it is not a MUST tool check. |
| 19 | **Residual edge cases from the final engineering review.** (1) A crash after `restore-control` writes the document, but before it saves, leaves no `control_restored` ledger event; the discarded copy is the only record. (2) With the project lock deliberately bypassed, repairing a torn ledger line can truncate a second writer's line. (3) `state.json` and the ledger have no key or outside anchor, so a writer with file access can rewrite both consistently. Tamper-evidence here covers accidents and agents working through vpg, not an adversary on the file system. (4) A `resumed` event can be written even when that resume's own save fails. | observed (engineering critic, final round; none blocking or major) | (1) Re-run `restore-control` or check the discarded copy. (2) Never bypass `vpg.lock`. (3) Back up or sign `.vpg/ledger.jsonl` outside the project for adversarial assurance. (4) Harmless: the chain still verifies. |
| 20 | **`vpg resolve` closes a defect; it does not override a reviewer.** A named human can close a defect no review can clear (feedback that no longer applies, a reviewer that only carries forward). A defect a current review still reports reopens when that review re-runs, and a failed current review still blocks the gate. There is no human waiver for a reviewer's false positive yet: the `waived` status exists, but no command sets it. | observed (`tests/test_bookkeeping.py`) | Fix the reviewer or its rubric and accept the change (`vpg accept-config`). A `vpg waive` command is a candidate. |
| 21 | **Engine upgrades are one-way for a run.** Since v1.1 the engine's code is part of the configuration a run accepted (`engine/<file>`), so every engine change blocks each run in flight until a named human accepts it. Once a newer engine has saved a run's state, an older engine cannot load it (new fields, strictly validated). | observed (`test_the_engine_code_is_part_of_the_configuration_a_run_accepted`; the replay of the first real run) | Roll forward, never back, under a live run, and copy the run's `.vpg/` before `vpg accept-config`: that copy, with the engine that wrote it, is the only way back (v1.5.1 adds escalation fields v1.5 cannot load). Accepting a change re-runs every review and the gate on the current version: since v1.5 a review's fingerprint includes the accepted configuration (`judged_under`), and prompts and agent role files are part of it, so no verdict carries over a change in how work is judged. A rollback to a checkpoint judged under another configuration re-checks the reviews and the gate the same way. Accepting also carries recorded passes over to the current fingerprint scheme where that is provable (limitation 27), so an unchanged producer still memo-skips. A producer's completion checks are the exception (limitation 30). |
| 22 | **Command-code fingerprints are conservative.** By default every file under the top-level directory of a script a command names counts. An edit anywhere in `pipeline/` therefore re-runs every node bound to a script there, for example the voice when only the scene engine changed. A file the pipeline generates into that tree re-runs them on every rewrite until it is listed in `command_code_exclude`. Code outside the project, installed packages and the interpreter version are not hashed. A node whose last pass predates v1.1 re-runs once at its next re-check, unless a named human keeps that pass with `vpg accept-config --adopt-code <node>` (limitation 27). | observed (`test_a_bound_commands_code_is_in_its_fingerprint`, `test_a_file_a_command_generates_is_reported_and_can_be_excluded`) | `command_code_exclude` for generated files; `command_deps` to narrow a node. `vpg status` warns, and the ledger records `command_code_changed`. |
| 23 | **Per-item progress is not counted separately.** A defect is a dimension and a check; the items it names are information. A correction that fixes two of three items counts as a failed correction of the whole check, so the three-corrections stop can come early. That is deliberate: per-item ids (layers, beats, cues) change between versions, and counting per item let a persisting problem reappear under a new id at zero. The review prompts don't yet ask reviewers for `element`. | observed (`test_findings_about_several_items_keep_every_description`, `test_a_problem_alternating_between_traces_still_escalates`) | **human:** an early stop is reported with the full rework history; Wei grants a fresh budget with `vpg unblock … --reset-budget`. Add `element` to the review prompts at the next production boundary. |
| 24 | **Human feedback can be linked to the wrong open defect.** A human's feedback is held unless it leads to an unresolved blocking defect, but the engine cannot tell whether that defect is about the same problem. An interpreter that links "this version is worse" to an unrelated open defect closes the feedback once rework fixes that defect. | assumed (engineering review, v1.2) | **human:** at N23, Wei checks each feedback item's defects (`.vpg/state.json` → `evaluation.feedback`; the release summary's human record flags feedback that was held). Map feedback to defects created for it whenever the match is not exact. |
| 25 | **The privacy scan sees only listed names, and only what OCR can read.** When `privacy.names` is declared, N23 refuses the release if any listed name is readable in the master. The scan decodes at the highest of 10 fps, a pinned `privacy.scan_fps` and the stream's stated `r_frame_rate` and `avg_frame_rate`, and fails closed if ffmpeg's fps filter drops any frame (a stream whose metadata understates its fastest stretch) or the rate is above 120 fps. `text-layers.json` can declare `live_windows` for moving product UI: each window frame is read in full (exact repeats excepted), and a window not fully decoded, or starting after the end, holds the release. Names set too small, stylised beyond OCR, absent from the list, or partly veiled as a lone surname can still escape. Missing or broken OCR, an unusable list, an unreadable video or an exceeded `privacy.time_budget_s` block the release. The scan is a release/publish check, not yet a routed N15 defect. | observed (`tests/test_privacy.py`, `tests/test_publish_and_reuse.py`, `tests/test_privacy_rates.py`; reported near-miss from the SRA film: a one-frame drawer leak between 10 fps samples) | Declare the list tenant-side, veil from DOM boxes on every captured frame, and declare live windows for moving UI. Run `python -m vpg.tools.privacy <project> <video>` before submitting a master (`--names <list>` checks against a list the project has not declared yet). |
| 26 | **The release summary's human record flags; it cannot prove.** N23 lists every action recorded under a human name with its prompt, latency and reason, and flags fast, reasonless, shared-reason, delegated and agent-filed ones. Since v1.7 it also lists every act an agent took under a grant, as the agent's, and the grants themselves. A slow, well-reasoned approval typed by an agent under the human's name still looks genuine (limitation 16). | observed (first real run: 25 actions under one name, 18 in under 60 s, 8 citing delegation; `tests/test_v17_governance.py`) | Wei reviews the flagged rows before releasing, and grants routine acts instead of lending his name. |
| 27 | **Carrying a pass over trusts its checkpoint, the ledger and file times.** Each pass records the fingerprint scheme it was recorded under (`last_pass_scheme`; v1.1 added a command's code, v1.5 narrowed `defects:rework` and tied reviews to the configuration). `vpg accept-config`, and a rollback to a checkpoint judged under another configuration, re-derive only passes recorded under an older scheme, from the checkpoint written when each passed, with the rework defects its `node_dispatched` event names. The old scheme must reproduce the recorded fingerprint exactly, and the new one is computed from that same checkpoint, so an input that changed since still re-runs the node. If the accepted change narrows a node's code (a tighter `command_deps` or a new `command_code_exclude`) and every file it still counts is byte-identical to the one its pass recorded, the pass is carried with the narrower code instead of re-running. A pass that cannot be reproduced (its checkpoint is gone; a node batched with it changed what it reads before that checkpoint was written; or its definition, prompt, a control document, rubric, project file or command line changed since) re-runs once. For a pass that predates code fingerprints, `--adopt-code <node>` is a human's word that the current code made it. The engine checks only that no code file was modified or re-created (its change time counts) in or after the second that pass began. So a deleted code file and code outside the project are not seen, and a `chmod`, a `git checkout` or a copied tree also refuses adoption. A pass made to fix defects is recorded without them (as every pass is since v1.5), so a node whose inputs are unchanged memo-skips after the fix instead of re-running once. | observed (`tests/test_carry_over.py`, 39 of 39 mutations caught; on a scratch copy of the SRA run it carried N07, N08, N11, N13 and N14 over, and refused N12 until `command_deps` named its real code: 14 other `pipeline/` files had changed after N12's pass began) | **human:** adopt only nodes whose code you know is unchanged, after narrowing their `command_deps`. |
| 28 | **Frozen sources are kept and watched; drift does not block.** When the inputs freeze (and, for a run frozen before v1.5, at its next step, blocked or not), each local source that still matches its registered hash is copied, read-only and verified on the bytes copied, to `.vpg/sources/<sha256>`. `vpg status` and every `vpg run` check the frozen sources and warn, by id only, when one is missing, changed, a hard link, or a symbolic link or inside a linked directory; a torn or edited copy is not counted as kept. A file is hashed again only when its inode, size, modification or change time differs from the one last verified (`.vpg/sources/verified.json`). A file changed in the last 2 s is hashed but not recorded, because on a file system with coarse timestamps a second edit in the same tick would keep its identity. The records only save work: N23 re-hashes every frozen source. N01 refuses a source that is a hard or symbolic link or lies inside a linked directory below `sources/`. A source that drifted before its copy was made has no copy. The copies hold the sources' content, so removing a source for privacy means removing its copy too. Since v1.5.1 the store carries a `.gitignore` ("*", put back when missing), so a commit of `.vpg/` never picks up the copies; the other side is that they then live only on the machine that ran the freeze. | observed (`tests/test_carry_over.py`; the SRA run's 53 sources were hard links, and 3 were rewritten from another project before any copy existed. Their registered bytes were recovered from local git objects and placed in the store by hand) | Restore a drifted source by deleting its file first (a hard link would carry the restore into another project's file), then copying the kept version back; or re-open intake with `vpg invalidate … n01_context_intake`. **human:** decide whether drift should block a run. |
| 29 | **A producer is fingerprinted by what it is given.** Since v1.5 a `defects:rework` input covers only the defects routed to the node, which is all its context (`VPG_CONTEXT` → `defects`, or the task packet) holds, so a new defect elsewhere no longer re-runs it. `defects:open` and `defects:all` still cover every defect, because engine tools read the whole state. A command or agent that reads `.vpg/state.json` directly sees more than it declares, and the engine cannot tell. | observed (`test_a_producer_memo_skips_when_only_another_nodes_defects_changed`; on the SRA run, D028–D035, routed to N13, changed the fingerprints of N11, N12 and N14, which never receive them) | Read defects through the context only; declare `defects:all` for a node that needs every defect. |
| 30 | **Only a node's own tool must declare the control documents it reads.** The engine refuses a graph whose `run.tool` reads a control document the node does not declare, since a change to it would neither change the node's fingerprint nor re-check it. The check reads the tool's source: a literal `ctx.fm("<doc>")`, `ctx.control_path("<doc>")` or `front_matter("<doc>")`, and `thresholds(ctx)` for evaluation.md, in the tool function and every function of its module it calls. A document named by a variable, or read through another module's helper, is not seen. N18 (production.md) and N20 (evaluation.md) did exactly that before v1.5. A custom workflow that fails the check after an engine upgrade must declare the document before `vpg accept-config` can run. Completion checks are not held to it: the checks of N07, N09, N12 and N14 read the evaluation.md thresholds, so a threshold change re-judges the reviews but not those producers' own checks. | observed (`test_a_tool_that_reads_an_undeclared_control_document_is_refused`; the default workflow before v1.5) | The reviews (N15–N20) check the same outputs downstream with the same thresholds. Candidate: declare `evaluation` on those producers at the next production boundary, when their re-run costs nothing. |
| 31 | **Caption sync trusts the words the voice node marks measured, and bounds the rest.** N18 keeps the time of every `timings.words` entry marked `measured: true`, once a unit's entries are its words in order and those times are finite, ordered and inside the unit's span, and never reads the time of any other entry. A word not measured is given the whole gap between the measured words around it (or the unit's edges, widened by the 0.1 s tolerance when the measured neighbour lies outside the span; across both neighbours when they overlap): it starts as early and ends as late as it could. That holds under a model: a unit's words follow one another inside its span. An unmeasured first or last word spoken outside the span while its measured neighbour is inside it is outside that model and can hide up to 0.1 s of lag or early clear. Within the model the no-lag (P2) and early-clear (P3) checks flag every cue that could lag or clear early, including some that are in sync: a cue that starts or ends on a word not measured, after a pause, is flagged although it may be right. A lead before such a word (P3) can be under-reported by up to the gap's width. A measured word the voice node aligned to the wrong occurrence is trusted as it is, and a unit with no measured word keeps the character spread over its whole span. | observed (`test_a_cue_that_could_lag_is_flagged_even_inside_a_run_not_measured`, where spreading an unmeasured run by characters passes a 0.45 s lag; `test_a_bounded_word_misses_no_violation_at_a_units_edges_or_between_overlapping_neighbours`, the critic's three counterexamples; 0 missed violations in 15,673 random units under the model; SRA a6 timings: 300 of 304 words measured, 4 bounded, no run longer than one word. The SRA side chat's 35 speech-chunked cues give 17 findings on the character spread, 3 when a unit with one unmeasured word fell back to it (v1.5), and 0 now) | Start and end cues on measured words: the finding says when the word was not measured. The voice node's alignment decides what is measured (for SRA, speech-recognition word times matched to the script). |
| 32 | **Changed code reaches the film at the next accepted configuration or rework cycle, not before.** Since v1.6, `vpg accept-config` and every rework cycle re-run each command node whose code changed since it last ran (before, nothing scheduled the re-check the status warning promised). Between those moments a code edit changes nothing, so a version reviewed meanwhile was built from the code recorded for it. A human-gated command node is never re-run this way. | observed (`tests/test_code_reaches_the_film.py`; SRA, ledger 1137: the take recorder's `sra-take/v2` fix sat in the pipeline while N11's registered take was `sra-take/v1`, until the owner invalidated N11 at seq 1147) | To run new code now, `vpg invalidate <project> <node> --actor <name> --reason "…"`. |
| 33 | **Convergence is measured by what the reviews find.** The trend has one row per version, merging all of the version's gates, and each budget is extended at most once per version. So re-judging a version never earns a second extension, and a version re-gated after a human's unblock keeps its progress. A budget is extended when the latest round resolved P1–P3 defects, found no more new ones than it resolved, and lowered their count or severity. A reviewer that stops reporting a problem it still sees would look like progress, and so would a round that re-judges nothing new. The same-defect guard (3 corrections) and the six independent reviews bound that, but the engine can't tell a real fix from a lowered bar. | observed (`tests/test_quality_budget.py`; the SRA trend at the block: v10 14 open → v11 4 open, 15 resolved, 1 new, which would have extended E43) | The release summary lists every extension with its reason, so the approver sees each one. Set `max_hours` for a hard wall-clock stop. |
| 34 | **Review rounds recorded before v1.6 are estimated in the trend.** Their open count is the gate's own, but resolved and new are counted from today's defects, whose severity may have changed since. The severity split comes from the gate's reason when it lists every open defect (a rework gate does; a blocked one may not). | observed (`budget.trend_rows`, `test_a_pre_v1_6_rework_gate_gives_its_severity_split_from_its_reason`; the SRA gates v1–v11) | Rows are marked "estimated". Gates from v1.6 on record each involved defect's severity at the time (`GateResult.trend.severities`). |
| 35 | **A pre-flight binds the files, not the judgement's scope.** The verdict is refused if any file it was shown changed, and actor ids are compared case-free with or without `agent:`, so the producer, the bound agent or a placeholder (`agent:`, `cli`, the dry-run actor) can't pass under another spelling. But the engine can't check what the reviewer actually looked at, or that two different ids are really different agents (`agent:critic` versus `agent:composer` is a label). A revised attempt's files stay registered under their attempt number until the next attempt replaces them. | observed (`tests/test_preflight.py`) | Use a reviewer with a different role and context. The release summary lists every verdict, and the six reviews still judge every version. |
| 36 | **A review is bound to bytes, not to attention.** Since v1.7 each review echoes the sha256 of the artifacts it judged (its packet prints them), and a review naming other bytes is refused. With `reviews: {binding: require, independence: require}`, an unbound review, or one submitted by an identity that produced what it judges (the attempt's submitter or the producing node's bound agent), is refused too; otherwise the release lists them. The engine can't check that the reviewer looked at every frame, and identities are labels (limitation 35). | observed (`tests/test_v17_governance.py`; SRA v10: three reviews judged a 06:17 dev build, not the registered master) | Set `reviews:` to require on real productions, and use reviewers with their own context. |
| 37 | **Redactions are declared and styled, not diffed against the capture.** Since v1.7 a text-layers `redaction` layer declares a bar, and N19 fails a declared blur or translucent veil (ACC-UI, P1). The privacy scan (limitation 25) checks no listed name is readable. No engine tool yet compares the UI around a redaction with the raw capture, so R-ACC-004 ("real UI pixels stay untouched") is still checked by review and project audits. R-ACC-004 stays "validated" until the SRA film ships: N03 fingerprints `knowledge/rules.json`, so demoting it mid-run would re-open Wei's approval. | observed (`tests/test_v17_governance.py`; triage #22) | v1.8: a `design:pixel_integrity` tool with a negative control, and demote R-ACC-004 to candidate after the release. |
| 38 | **An agent's note waits; a human's re-opens.** Since v1.7 `vpg feedback` from an agent re-opens nothing: it waits for a named human's (or a granted agent's) triage, holds the gate from passing, and blocks N23. Human feedback still re-opens a passed gate, and is interpreted at the next N21, not at once. | observed (`tests/test_v17_governance.py`) | Triage agents' notes when they arrive (`vpg status` lists them). |

## Unverified research items that matter to production

These are from the [research](research/graph-engineering-and-tools.md) §6. None blocks the engine; all block specific tool choices.

- Whether Sora 2 on Azure AI Foundry continues after OpenAI's own API shutdown (2026-09-24); the Foundry preview is listed as retiring 2026-10-15.
- Which Remotion licence text is operative (`LICENSE.md` vs the FAQ). **human:** clear company-use licensing before adopting Remotion.
- YouTube's official loudness target: −14 LUFS is industry-inferred. vpg defaults to −16 LUFS, from Round 07.
- The exact SMPTE ST 2046-1 safe-area percentages, which are paywalled. vpg uses Round 07's title-safe box.
- WebVTT support in ffmpeg's `subtitles` filter. vpg writes SRT.

## Unrecoverable from the production history

All six items are reported from the private platform-film case study. Its customer sources and production history
are retained only in the originating workspace, not in the community repository.

1. **The full raw transcript of the production session.** Wei's messages M1–M8 were recovered and cited as evidence instead.
2. **Continuous human audiovisual review of the reference recordings.** The sources record sampled frames, transcripts and captions, not continuous listening.
3. **Verbatim meeting quotes and participant identities.** These are withheld by the confidentiality rule. Terminology is summarised and cited.
4. **The subjective warmth and naturalness of the final Round 07 voice.** No human listening pass is recorded, and instruments cannot certify perception.
5. **Exact billing cost of cloud generation.** Request counts and caps are recorded; unverified dollar estimates were deliberately avoided.
6. **Proof of the cause of the early session crash.** Renderer crashes were observed. A large history was a plausible trigger, but no editor defect was patched.

## Only a human can close

- Listening sign-off at N23: voice and music.
- Threshold calibration (item 1).
